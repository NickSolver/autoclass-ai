# Автокласс AI

Закрытый портал анализа и контроля качества телефонных звонков для группы компаний.
Техническое задание — [docs/avtoklass_ai_tz_v1_0.md](docs/avtoklass_ai_tz_v1_0.md).

**Текущее состояние: этапы A–E.**
- A — вход (с двухфакторной аутентификацией), оргструктура, сотрудники, пользователи, роли
  с областями доступа, аудит.
- B — ручная загрузка звонков (MP3/WAV/M4A), проверка файлов, дубли, приватное хранилище,
  очередь подготовки аудио, список и карточка звонка с плеером ([ADR-0003](docs/adr/0003-manual-call-intake.md)).
- C — распознавание и ИИ-оценка через сменяемых провайдеров: тестовый провайдер и любой OpenAI-совместимый
  API (готовая настройка DeepSeek), проверка доказательств, оценка по DEMO-чек-листам, журнал и стоимость
  вызовов ([ADR-0004](docs/adr/0004-ai-pipeline.md)).
- D — конструктор версионируемых чек-листов (сравнение версий, проверка на звонке) и визуальный конструктор
  бизнес-процессов: условия, выбор чек-листов, задачи на проверку, симуляция, публикация; запущенные экземпляры
  закреплены за своей версией ([ADR-0006](docs/adr/0006-workflow-and-checklist-designers.md)).
- E — ручная проверка с правками (новая ревизия, результат ИИ сохраняется), исправление расшифровки,
  апелляции с независимым решением, аналитика с честными знаменателями и выгрузка CSV
  ([ADR-0007](docs/adr/0007-review-appeals-analytics.md)).

Источники звонков Calltouch и «Лягушка» — этап F (после документации и доступов); в интерфейсе показаны как
«Модуль в разработке», без данных и действий.

## Стек

Laravel 13 (PHP 8.3) · MySQL 8.4 · Redis + Horizon · FFmpeg · Vue 3 + TypeScript + Pinia + Vue Router · Vite 8 · Tailwind 4.
Модульный монолит: `app/Domain/{Identity,Organization,Audit,CallIntake,Audio,AiProviders,Transcription,Evaluation}`, API — `app/Http`.

Сервисы Docker: `app` (PHP-FPM), `horizon` (обработчик очереди), `nginx`, `mysql`, `redis`.
Панель очередей — http://localhost:8080/horizon (только администратору уровня группы).

## Запуск (Docker + Node на хосте)

```bash
cp .env.example .env            # затем DB_PASSWORD=secret (или ваш MYSQL_PASSWORD)
docker compose up -d --build
docker compose exec app composer install
docker compose exec app php artisan key:generate
docker compose exec app php artisan migrate --seed
npm ci && npm run build          # или npm run dev для разработки
```

Портал: http://localhost:8080. Образ `app` собирается с UID/GID пользователя хоста
(по умолчанию 1000; иначе задайте `UID`/`GID` в окружении) — это нужно для записи в `storage/`.

### Первый администратор

Публичной регистрации нет. Первый суперадминистратор создаётся консольной командой;
пароль вводится интерактивно и не попадает в историю shell:

```bash
docker compose exec app php artisan avtoklass:create-superadmin
```

Команда создаёт группу компаний (если её нет), шаблоны ролей и пользователя. Если активный
суперадминистратор уже есть, команда откажет (ещё одного — с флагом `--additional`).

### Демоданные (только вне production)

`php artisan db:seed` загружает **синтетическую** группу «Демо», две компании, центры, отделы,
вымышленных сотрудников и пользователей. Пароль всех демо-пользователей: `Demo-Password-2026`.

| Логин | Роль | Область |
|---|---|---|
| `demo.admin` | Суперадминистратор | вся группа |
| `demo.north.admin` / `demo.south.admin` | Администратор компании | «Север» / «Юг» |
| `demo.north.director` | Директор | компания «Север» |
| `demo.qc` | Контролёр качества | вся группа |
| `demo.north.rop` | РОП | отдел продаж ДЦ Северный-1 |
| `demo.north.manager` | Сотрудник | собственные записи |

Письма (ссылки сброса пароля) в разработке пишутся в `storage/logs/laravel.log` (`MAIL_MAILER=log`).

## Проверки

```bash
docker compose exec app php artisan test       # PHPUnit, база laravel_test (MySQL)
docker compose exec app composer lint           # Pint
docker compose exec app composer analyse        # Larastan, level 5
npm run lint && npm run typecheck && npm test   # ESLint, vue-tsc, Vitest
```

Браузерные e2e-тесты (Playwright) — на **изолированном стенде**: отдельный контейнер, база `laravel_e2e`,
порт 8081; перед каждым прогоном стенд пересоздаётся. Рабочая база не затрагивается.
Браузер работает в контейнере Playwright — на хост ставить ничего не нужно.

```bash
npm run test:e2e
```

База для тестов создаётся один раз:
`CREATE DATABASE laravel_test; GRANT ALL ON laravel_test.* TO 'laravel'@'%';`

CI: [.github/workflows/ci.yml](.github/workflows/ci.yml) — стиль, статанализ, миграции up/down/up, тесты, сборка.

## API

`/api/v1`, сессия в cookie + CSRF (`XSRF-TOKEN` → заголовок `X-XSRF-TOKEN`).
OpenAPI генерируется из кода (Scramble): UI — `/docs/api`, JSON — `/docs/api.json`
(в окружении `local`; в остальных доступ закрыт по умолчанию).

## Модель доступа (кратко)

Подробно — [ADR-0001](docs/adr/0001-rbac-and-org-scope.md).

- Итоговое право = действие × область (группа / компания / центр / отдел / собственные записи); область наследуется вниз.
- Запрет по умолчанию; проверка на сервере на каждом запросе. Объекты вне области отдаются как **404**.
- Код проверяет только права (`App\Domain\Identity\Permission`), не коды ролей. Роли редактируются в интерфейсе.
- Выдать роль можно, только обладая всеми её правами в нужной области. Управлять пользователем можно,
  только если его подразделение и все его роли — в вашей области.
- Нельзя оставить систему без активного суперадминистратора; нельзя отключить себя.
- Двухфакторная аутентификация (TOTP) обязательна для прав управления; 7 дней на подключение,
  резервные коды, сброс администратором, повторный ввод кода для критичных действий — [ADR-0002](docs/adr/0002-mfa.md).
  Аварийный сброс: `docker compose exec app php artisan avtoklass:mfa-reset <логин>`.
- Аудит: все изменения справочников (старое/новое значение), входы, выходы, сбросы паролей, выдача ролей.
  Пароли и хеши в журнал не попадают. Записи аудита неизменяемы.

## Известные ограничения

- Нет CSP-заголовка (мешает dev-серверу Vite); добавить при настройке production-окружения.
- E2E-тесты в CI не запускаются (нужен Docker Compose в раннере) — только локально через `npm run test:e2e`.
- Перенос подразделения в другую компанию не поддерживается (родитель неизменяем; ADR-0001).
- Шаблон «Администратор компании» содержит бизнес-права звонков/оценок/аналитики своей компании —
  без них он не может назначать роли директора/РОП/контролёра (правило против эскалации; ADR-0001, п. 5).
- Удаления подразделений и пользователей нет — только деактивация.
- Сроки хранения, юридические основания обработки, интеграции Calltouch/«Лягушка» — вне этапа A (ТЗ, разд. 17).
- Записи звонков: при хранении в S3 нет перемотки в плеере (нужны подписанные ссылки); нет антивирусной
  проверки файлов, квот на загрузку и возобновляемой загрузки больших файлов (ADR-0003).
- Исключение звонка вместо удаления: удаление и обезличивание — после согласования политики хранения.
- ИИ: драйверы распознавания (Яндекс, T-Bank, OpenAI) сверены со спецификациями, но на живом API проверяются
  при первом ключе; SaluteSpeech, МТС, ЦРТ — ждут документации или доступа; Google скрыт (ADR-0005). Чек-листы — DEMO до получения реальных от заказчика; без опубликованного процесса действует выбор по направлению звонка; уведомлений о проверках нет — очередь на экране «Ручные проверки».
- Передача записей внешним провайдерам выключена по умолчанию; включать — только после юридической проверки (ТЗ, разд. 12).

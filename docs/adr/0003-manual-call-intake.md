# ADR-0003. Ручная загрузка звонков и подготовка аудио (этап B)

- **Статус:** принято
- **Дата:** 23.10.2026
- **Связано с:** ТЗ v1.0, разд. 4.1, 4.2, 5, 12, 15 (этап B), 17; ADR-0001

## Решения

1. **Один файл — один запрос.** Пакет — последовательность запросов из интерфейса (по два параллельно)
   с прогрессом по каждому файлу. Каждый запрос несёт заголовок `Idempotency-Key`: повтор того же
   запроса (обрыв связи, двойная отправка) возвращает уже созданный звонок (`source + external_id`
   уникальны, ТЗ разд. 4.1). Ключ, использованный другим пользователем, — 409 без раскрытия звонка.
2. **Проверка файла — при загрузке, до создания звонка.** Сначала сигнатура содержимого
   (MP3 / WAV / MP4-контейнер), затем `ffprobe` с **явно заданным форматом** и
   `-protocol_whitelist file`. Это не даёт выдать за аудио плейлист HLS/`concat`, через который
   ffmpeg прочитал бы чужие файлы сервера или обратился в сеть. Отклоняются: неподдерживаемый формат,
   повреждённый файл, файл без звука, файл с видео, длительность вне лимитов. Ответ — 422 с понятной
   причиной и короткой диагностикой без путей сервера; в хранилище ничего не остаётся.
3. **Дубли** определяются по SHA-256 оригинала. Повторная загрузка того же содержимого — 409
   `duplicate_audio`; загрузить можно только с явным подтверждением (`confirm_duplicate`), звонок
   получает ссылку `duplicate_of`. Ничего не удаляется. Дубль в чужом подразделении не раскрывается
   (сообщается только факт).
4. **Хранение.** Приватный диск `calls`; путь — `ГГГГ/ММ/<uuid>/original.<формат>` (имя файла
   пользователя в путь не попадает, хранится только для отображения). Оригинал неизменяем;
   нормализованная копия для распознавания — `normalized.wav` (моно, 16 кГц, PCM 16 бит).
5. **Прослушивание** — только через `GET /api/v1/calls/{id}/audio` с проверкой прав, без публичных
   ссылок. Для локального диска — перемотка (HTTP Range). Скачивание — отдельное право
   `audio.download` и всегда запись в аудит; аудит прослушивания включается настройкой
   `CALLS_AUDIT_PLAYBACK`. При переходе на S3 отдача идёт потоком **без перемотки** — для перемотки
   потребуются короткоживущие подписанные ссылки (отдельная задача).
6. **Технический статус.** Список статусов ТЗ после подготовки сразу переходит к распознаванию, а
   модуля ASR на этапе B нет. Введён статус `awaiting_transcription` («Ожидает распознавания»), чтобы
   не изображать несуществующую обработку. Этап C продолжит конвейер с этого статуса.
7. **Очередь** — Redis + Horizon, очередь `audio` (таймаут задачи 900 с, `retry_after` 960 с).
   Задача подготовки идемпотентна: повторный запуск перезаписывает нормализованную копию и не
   создаёт новых сущностей; каждая попытка пишется в `call_processing_attempts`. 3 попытки с паузами;
   ошибки, повтор которых бессмыслен (нет исходного файла), — сразу статус «Ошибка обработки»
   с причиной. Звонок при ошибке не теряется. Панель `/horizon` — только администратору уровня группы.
8. **Исключение вместо удаления.** `calls.delete` в этапе B означает «исключить из обработки» с
   обязательной причиной; запись и история сохраняются, вернуть можно повторной обработкой.
   Настоящее удаление и обезличивание — по политике хранения (ТЗ разд. 12), пока не согласованной.
9. **Сопоставление.** Подразделение обязательно, сотрудник — нет: «Не установлен» даёт статус
   `needs_employee` и фильтр «Требует сопоставления» (ТЗ разд. 17 п. 4). Исправление подразделения и
   сотрудника требует права загрузки в старом и новом подразделении; снимок оргструктуры
   пересоздаётся, прежний сохраняется в аудите.
10. **Лимиты** — `config/calls.php` (по умолчанию 100 МБ, от 1 с до 120 мин, до 50 файлов за раз).
    Окончательные — после пилота. Лимит размера согласован с PHP (`Dockerfile`) и nginx.

## Права (дополнение к шаблонам ролей)

Администратор компании получил `calls.upload`, `calls.reprocess`, `calls.delete`, `audio.download`
в своей компании. Существующие роли в развёрнутой базе сидер не меняет — права добавляются в интерфейсе.

## Не входит в этап B

Распознавание, классификация, оценка (C, D); сохранённые представления списка; антивирусная проверка
файлов; квоты на загрузку; возобновляемая загрузка больших файлов (ТЗ разд. 17 п. 7 — развитие).
